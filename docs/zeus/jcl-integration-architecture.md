# Zeus における JCL サポート実装詳細解説: パース・計画・実行シーケンス

本ドキュメントでは、**Zeus（Rust による z/OS アプリケーションランタイム）** における **JCL（Job Control Language）実行エンジン（`zeus-jcl` / `zjob`）** について、構文解析、プロシージャ（PROC）展開、条件分岐（COND / IF-THEN-ELSE）、データセットライフサイクル（DISP / GDG / VSAM）、および内蔵ユーティリティ連携を含めて詳細に解説します。

---

## 1. JCL エンジンのアーキテクチャ概要

### 1.1 目的と「コンテナ不要の直接高速実行」
メインフレーム（z/OS）における基幹バッチワークロードは、JCL によってジョブステップの順序、入出力データセットの割り当て、条件判定、プログラム起動が定義されています。

GnuCOBOL 等のトランスパイル環境では、ステップごとに Docker コンテナを起動して環境変数やマウントを設定する構成をとることが多いですが、Zeus の JCL エンジン **`zjob`** は、**「軽量・高速な Rust 単一バイナリ内で、コンテナを一切起動することなくバッチジョブを直接実行する」** アーキテクチャを採用しています。これにより、秒単位のプロセス起動オーバーヘッドをミリ秒以下に短縮し、何千ステップにも及ぶ大規模夜間バッチを高速に処理できます。

### 1.2 全体アーキテクチャ構成図

```text
+--------------------------------------------------------------------------+
|                          JCL ソース原本 (.jcl)                           |
|  //JOBNAME  JOB  (ACCT),'TITLE',CLASS=A,MSGCLASS=X                       |
|  //STEP01   EXEC PROC=MYPROC,PARM='...'                                  |
|  //DD1      DD   DSN=MY.DATASET,DISP=(NEW,CATLG,DELETE),SPACE=(CYL,(5,1))|
|  //SYSIN    DD   * (インストリームデータ)                                 |
+--------------------------------------------------------------------------+
                                     |
                                     v  [zjob run / crates/zeus-jcl]
+--------------------------------------------------------------------------+
| 1. パース & 展開層 (zeus-jcl: job.rs)                                    |
|   - 80 桁パンチカード形式・継続行規則の解析 (//, //*, /*, カンマ継続)       |
|   - JCLLIB ORDER / INCLUDE MEMBER の再帰探索と展開                       |
|   - カタログド PROC / インストリーム PROC の展開 & 引数・シンボル置換     |
|   - step.ddname による DD カードの階層的オーバーライド                   |
|   - IF / THEN / ELSE / ENDIF および COND パラメータの AST 構築           |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 2. データセット計画 & カタログ層 (zeus-ds)                                |
|   - カタログ照会 (順次 FB/VB, PDS/PDSE, VSAM KSDS/ESDS/RRDS/AIX)          |
|   - GDG (Generation Data Group) 相対世代番号 (+1, 0, -1) の絶対世代解決   |
|   - DISP 状態マシン遷移 (NEW/OLD/SHR/MOD -> PASS/KEEP/CATLG/DELETE)       |
|   - 一時データセット (&&TEMP) のジョブ内スコープ管理                      |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 3. ステップ実行 & ディスパッチ層 (zeus-jcl: main.rs, utils/)             |
|   - 前ステップ終了コード (RC / ABEND) に基づく COND / IF ガード評価      |
|   - 実行対象のルーティング:                                              |
|     * Zeus COBOL / PL/I プログラム: ZIR / ネイティブ直接インプロセス実行  |
|     * TSO バッチ (IKJEFT01): SYSTSIN コマンドパーサー                     |
|     * Db2 バッチ (DSNTEP2 / DSNTIAUL): zeus-jcl/utils/db2util.rs         |
|     * IMS バッチ (DFSRRC00): zeus-jcl/ims.rs                              |
|     * 内蔵ユーティリティ: IEFBR14, IEBGENER, IDCAMS, SORT, IEBCOPY       |
|   - SYSOUT / JES スプール出力のキャプチャ & ジョブログ生成               |
+--------------------------------------------------------------------------+
```

## 2. 構文解析（Lexing / Parsing）と PROC 展開

### 2.1 80桁カード解析と継続規則
JCL の字句解析器（`crates/zeus-jcl/src/job.rs`）は、z/OS の伝統的なパンチカード規則を厳格に処理します:
1. **カード行の種別**:
   - `//`: JCL ステートメント（JOB, EXEC, DD, SET, PROC, PEND, IF, ELSE, ENDIF）。
   - `//*`: コメント文（解析器により無視）。
   - `/*`: デリミタ文（インストリームデータの終端）。
2. **継続行（Continuation）**:
   - 先頭 2 文字が `//` で、3 文字目以降に空白が続き、前行のオペランドがカンマ `,` で終了している場合、単一の論理ステートメントとして連結。
3. **インストリームデータ (`DD *` / `DD DATA`)**:
   - `DD *`: 次行から `/*` または新たな `//` が現れるまでをインストリームデータバッファへ蓄積。
   - `DD DATA,DLM=xx`: 内部に `//` を含む JCL や制御文を安全に渡すため、指定された 2 文字デリミタ（`DLM=`）が出現するまでをデータ行としてキャプチャ。

### 2.2 プロシージャ（PROC）とシンボル置換
- **`JCLLIB ORDER=(...)`**: プロシージャ検索パスを定義。カタログ上の PDS メンバーまたはローカルディレクトリから該当ファイルを探索。
- **PROC 展開と引数マージ**:
  - `EXEC procname,PARAM1=VAL1` の呼び出し時、PROC 内で定義されたデフォルトパラメータに対して呼び出し元のキーワードパラメータを上書き。
  - シンボル置換（`&VAR`）は再帰的に評価され、末尾のピリオド `.` は区切り文字として消費（例: `&DSPREF..DATA` → `USER.DATA`）。
- **DD オーバーライド**:
  - `//STEP01.SYSIN DD ...` のように指定された場合、プロシージャ内の該当前ステップの DD カードのオペランドを正確に置換・追加マージ。

## 3. データセット管理と DISP 状態遷移

Zeus のデータセット管理サブシステム（`crates/zeus-ds`）は、メインフレームのカタログ機能および DISP パラメータのライフサイクルを完全に再現します。

### 3.1 DISP 状態遷移表
JCL の `DISP=(status, normal-disp, abnormal-disp)` は以下の状態マシンとして実装されています:

| 初期状態 (Status) | ステップ正常終了時 (Normal Disp) | ステップ異常終了時 (Abnormal Disp) | 物理操作 |
| :--- | :--- | :--- | :--- |
| **`NEW`** | `CATLG` | `DELETE` | ファイルを新規作成。正常時はカタログに登録、異常時は物理ファイルを削除。 |
| **`NEW`** | `PASS` | `DELETE` | 次のステップへデータセットポインタを渡す（ジョブ終了まで一時保持）。 |
| **`OLD` / `SHR`** | `KEEP` | `KEEP` | 既存ファイルを開く。終了後もファイルとカタログをそのまま保持。 |
| **`MOD`** | `CATLG` / `KEEP` | `KEEP` | 既存ファイルが存在すれば末尾追記、存在しなければ新規作成して追記。 |

### 3.2 GDG（Generation Data Group）の解決
Zeus は GDG の相対世代解決をサポートしています:
- `DSN=MY.GDG(+1)`: 次の新しい世代を割り当て（ジョブ完了時に絶対世代番号 `G0001V00` 等として確定）。
- `DSN=MY.GDG(0)`: カレントの最新有効世代を参照。
- `DSN=MY.GDG(-1)`: 1 つ前の旧世代を参照。

## 4. 条件分岐（COND / IF-THEN-ELSE）

### 4.1 COND パラメータの逆論理評価
メインフレーム JCL の `COND=(code, operator, step)` は**「条件が真（TRUE）の場合にそのステップをスキップ（実行除外）する」**という独特の逆論理規則を持ちます。Zeus はこの仕様に完全準拠しています:
- `COND=(4,LT)`: 「4 < 過去のステップ復帰コード」が真ならステップをスキップ（＝復帰コードが 4 以下のときのみ実行）。
- `COND=EVEN`: 直前のステップが ABEND（異常終了）していても実行。
- `COND=ONLY`: 直前のステップが ABEND した場合にのみ実行。

### 4.2 構造化 IF 構文
```jcl
//IF1     IF (STEP01.RC = 0 & STEP02.RUN = TRUE) THEN
//STEP03  EXEC PGM=PROG03
//        ELSE
//STEP04  EXEC PGM=PROG04
//ENDIF   ENDIF
```
Zeus の JCL 解析器は、上記の構造化 IF 文を AST ノードとして構築し、先行ステップの実行結果コンテキストに基づいて実行ブランチを動的に切り替えます。

## 5. 内蔵ユーティリティの実装

Zeus は、メインフレームで日常的に使用される標準ユーティリティを Rust で高速エミュレートしています:

1. **`IEFBR14`**:
   ダミープログラム。プログラム自身は何もしないが、DD カードの `DISP` 処理を実行させることで、データセットの新規作成・カタログ登録・削除を行う。
2. **`IEBGENER`**:
   順次データセットまたは PDS メンバーのレコードコピー。DD `SYSUT1` から読み込み、`SYSUT2` へ出力。
3. **`IDCAMS` (VSAM ユーティリティ)**:
   - `DEFINE CLUSTER`: VSAM KSDS / ESDS / RRDS の定義。キー位置・長さ・レコード長を設定。
   - `DELETE`: クラスターまたはデータセットの削除。
   - `REPRO`: 順次データセットから VSAM クラスターへの一括ロード、または VSAM のバックアップ出力。
4. **`SORT` (DFSORT / SyncSort サブセット)**:
   DD `SORTIN` から読み込み、`SYSIN` の `SORT FIELDS=(pos, len, type, order)` 制御文に従って EBCDIC 照合順序でレコードを並べ替え、`SORTOUT` へ出力。
5. **`IKJEFT01` (TSO バッチ)**:
   DD `SYSTSIN` 内の TSO コマンド群を解析し、プログラム起動や Db2 DSN コマンドを実行。
6. **`DB2UTIL` (`crates/zeus-jcl/src/utils/db2util.rs`)**:
   `DSNTIAD`, `DSNTEP2`, `DSNTIAUL` 相当の SQL 実行・データアンロードユーティリティ。

## 6. GnuCOBOL 方式（jclsh）との比較

| 比較項目 | Zeus (`zjob`) | GnuCOBOL (`extras/jclsh`) |
| :--- | :--- | :--- |
| **ステップ実行モデル** | **Zeus ランタイム内インプロセス高速実行** | ステップごとに Docker コンテナを起動・実行 |
| **起動速度** | **ミリ秒オーダー（極めて高速）** | コンテナ起動オーバーヘッド（数十ミリ〜数秒） |
| **環境変数注入** | 内部の実行コンテキストで直接バインド | Docker `-e` 引数およびコンテナ内環境変数 |
| **VSAM / データセット** | `zeus-ds` による EBCDIC ネイティブ保持 | ホストファイルシステムへのマウントと変換 |
| **スプール管理** | 単一ジョブディレクトリ配下に構造化 JSON 保存 | `result.json` および SYSOUT ファイル |
