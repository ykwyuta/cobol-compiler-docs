# z/OS PL/I 構文対応状況マトリクス (Enterprise PL/I for z/OS Syntax Compliance Matrix)

## 1. 概要と評価基準

本ドキュメントは、IBM 公式の **Enterprise PL/I for z/OS (Language Reference SC27-8940)** で規定されている PL/I (Programming Language One) 言語仕様に基づき、本研究リポジトリで比較対象としている **3つのプロジェクト（Zeus、GnuCOBOL zosplus、cobol-on-java）** の準拠状況・サポート範囲・制限事項を横断的にまとめたものです。

メインフレームの基幹システムでは、COBOL と並び PL/I で記述された資産（例: Bank-of-Z のバッチ帳票出力 `BNKSTMT.pli` や IMS オンライン `IBLOGIN.pli` 等）が重要な役割を果たしています。各プロジェクトがどのように PL/I を解釈・実行しているかを明確にします。

### 評価基準・記号の定義
- **●（完全対応）**: 当該構文を構文解析でき、Enterprise PL/I 互換の意味論（ランタイム実行結果）を充足している。
- **▲（部分対応 / 制限あり）**: 主要な構文は通るが、特定の方言オプション・一部の型・未対応サブセットが存在する。
- **×（未対応）**: 現時点でパーサーで拒否される、またはコンパイル/実行が未実装。
- **―（対象外 / 非推奨）**: 意図的にサポート対象外としている機能。

## 11. 3プロジェクトの PL/I 実装アーキテクチャ比較と論点

```
+---------------------------------------------------------------------------------------------------+
| [Zeus (Rust)]           : Enterprise PL/I V5.3 仕様書準拠のフルスタックコンパイラ・ランタイム       |
|                           - 再帰下降パーサー -> 型付きIR -> インタプリタ実行                        |
|                           - COBOLと同一の実行単位記憶域 (EBCDIC/アドレス空間) を共有                 |
|                           - CICS, Db2 (動的SQL/SQLDA), IMS, プリプロセッサマクロまで網羅            |
+---------------------------------------------------------------------------------------------------+
| [GnuCOBOL zosplus (C)]  : 実資産 (Bank-of-Z: BNKSTMT.pli) 特化のトランスパイラ (pl1c)             |
|                           - Rust 製トランスパイラ -> C11 コード生成 -> GCC/Clang ネイティブ実行     |
|                           - libpli ランタイム (固定長レコードI/O, Db2 CLI ラッパー, PUT EDIT)       |
|                           - 超高速なネイティブ実行を最優先とし、高度な PL/I 動的機能は割り切り      |
+---------------------------------------------------------------------------------------------------+
| [cobol-on-java (JVM)]   : 実資産 (BNKSTMT.pli / IBLOGIN.pli) 完全無修正コンパイル特化 (pli-compiler)|
|                           - ANTLR4 構文解析 -> ASM による JVM バイトコード (.class) 直接生成       |
|                           - 共通メモリ上の連続バイトビュー、Db2 ポート、IMS PLITDLI を COBOL と共用 |
|                           - 検証レベル V2 (参照出力との差分ゼロ) を重視し、必要構文を確実に実装     |
+---------------------------------------------------------------------------------------------------+
```

### 主な技術論点とトレードオフ

1. **実装スコープの選定方針（網羅型 vs 資産特化型）**
   - **Zeus**: Enterprise PL/I の膨大な言語仕様（再帰、AUTOMATIC/CONTROLLED 記憶域、複素数、動的 SQL、マクロプリプロセッサ）を仕様書からクリーンルーム設計で網羅的に実装。
   - **GnuCOBOL / cobol-on-java**: メインフレーム移行で現実に発生する PL/I 資産（Bank-of-Z のバッチ帳票と IMS ログイン）を**「1行も修正せずに翻訳・完全一致実行できること」**をターゲットとし、過度な言語仕様肥大化を避けて実用的なサブセットをピンポイントで実装。

2. **メモリモデルと他言語（COBOL）との結合**
   - **Zeus**: 単一のアドレス空間を COBOL と PL/I が `attach`/`detach` して共有。ポインタ参照や `BASED` 構造体のメモリ番地を言語間でそのまま相互受け渡し可能。
   - **GnuCOBOL**: C言語のメモリ空間へマッピング。`libpli` の内部管理領域と GnuCOBOL の `libcob` が別系統となるため、言語間連携時は引数の値コピーまたは C ABI 経由で受け渡し。
   - **cobol-on-java**: `cobol-runtime` のバイト配列モデル（`DataView`）をそのまま PL/I でも共用。COBOL と同じ JVM クラス・メソッド呼出し規約に正規化し、シームレスな相互呼び出しを実現。

3. **CICS / Db2 / IMS との統合度**
   - **Zeus**: PL/I 用の BMS マップ生成（`zbms --pli`）や `DFHEIBLK` 自動挿入を備え、CICS 上で COBOL と PL/I が同一トランザクションとして動作可能。
   - **GnuCOBOL / cobol-on-java**: バッチ（`BNKSTMT.pli` の Db2 カーソル操作・帳票出力）および IMS（`IBLOGIN.pli` の `PLITDLI` 電文処理）に焦点を当てており、CICS 画面処理は COBOL 側に集約する設計。
