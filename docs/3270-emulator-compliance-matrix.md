# 3270 エミュレータ・データストリーム仕様準拠状況レポート
(IBM 3270 Data Stream / TN3270 / TN3270E Compliance Matrix)

## 1. 概要と評価基準

本ドキュメントは、IBM メインフレーム（z/OS）のオンライントランザクション（CICS / IMS TM 等）で使用される **3270 表示装置・端末プロトコル（IBM 3270 Data Stream、TN3270、TN3270E、BMS）** の公式仕様に基づき、本研究リポジトリで比較対象としている **3つのプロジェクト（Zeus、GnuCOBOL zosplus、cobol-on-java）** の実装状況・仕様準拠度・アーキテクチャ方針を横断的に比較・検証したレポートです。

### 準拠仕様の典拠
- **IBM GA23-0059**: *IBM 3270 Information Display System: Data Stream Programmer's Reference*
- **RFC 854 / 855**: *Telnet Protocol Specification*
- **RFC 1576**: *TN3270 Current Practices*
- **RFC 2355**: *TN3270 Enhancements (TN3270E)*
- **IBM SC34-6011**: *CICS Basic Mapping Support (BMS) Guide*

### 評価基準・記号の定義
- **●（完全対応）**: 当該プロトコル・オーダー・属性を実装し、実機エミュレータまたはブラウザ上で正常に動作する。
- **▲（部分対応 / 制限あり）**: 基本機能は動作するが、特定の拡張属性・モード・オプションに未対応がある。
- **×（未対応）**: 当該仕様・コマンドを実装していない。
- **―（対象外 / 別アプローチ）**: 端末プロトコルを直接解釈せず、上位モデル（Web UI 等）で代替している。

## 10. 主要な技術論点とトレードオフ

### 1. 「端末エミュレータの維持」 vs 「モダン Web UI への脱却」
- **Zeus / GnuCOBOL**:
  - **利点**: 既存のメインフレーム運用者・ユーザーが使い慣れた `x3270`、PCOMM (IBM Personal Communications) などのエミュレータをそのまま利用可能。ショートカットキーや打鍵速度の体感が変わらない。
  - **論点**: TCP 3270 ポートの通信開放、各クライアント端末へのエミュレータソフト導入・管理が必要。
- **cobol-on-java**:
  - **利点**: ブラウザ（HTTPS / 443）だけで動作するため、ゼロインストールでセキュア。Spring Security による認証やロードバランサーとの親和性が極めて高い。
  - **論点**: ブラウザ上で 24×80 の等幅レイアウトを崩さずに描画する技術的難易度（CSS Flex/Grid、IME 制御、Tab キー移動、ドラッグ選択等）。

### 2. プロセス分離とセッション管理モデル
- **Zeus**: 単一プロセス内で非同期コルーチン（TCB 模倣）により全端末セッションを制御。メモリフットプリントが最小。
- **GnuCOBOL**: `cobcicsd` サーバーが端末接続をプールし、トランザクション発生ごとに COBOL ワーカーを起動・パイプ制御。プロセスの独立性が高く、ワーカーがクラッシュしてもサーバーが保護される。
- **cobol-on-java**: Spring Boot の HTTP セッション・会話ストア（Conversation Store）により、COMMAREA と画面状態をステートレス/分散キャッシュ（Redis 等）に退避可能なクラウドネイティブ設計。

### 3. 周辺機器（3287 プリンタ、IND$FILE）の扱い
- メインフレームの帳票印刷を端末連携プリンタ（3287）で行っている資産や、ファイル転送（`IND$FILE`）に依存している業務フローがある場合、**Zeus のような低レイヤプロトコルの忠実な実装**が移行の唯一の選択肢となります。
