# cobol-on-java における PL/I 統合アーキテクチャと JVM バイトコード生成詳細解説

本ドキュメントでは、**cobol-on-java（Java 21 / JVM バイトコード直接生成方式）** における **PL/I コンパイラ・ランタイムサブシステム（`pli-compiler`）** について、PL/I ソースから JVM バイトコード（`.class`）への直接生成アーキテクチャ、`ByteArrayView` による z/OS メモリレイアウトの忠実な再現、および同一 JVM 上における COBOL・PL/I・HLASM（アセンブラ）のシームレスな多言語相互呼出機構を詳細に解説します。

---

## 1. PL/I 処理系のアーキテクチャ概要

### 1.1 目的と「直接 JVM バイトコード生成」の思想
メインフレーム（z/OS）上で稼働するミッションクリティカルなシステムでは、COBOL プログラムと PL/I プログラムが同一のトランザクションやバッチジョブ内で相互に呼び出し合う構成が頻繁に見られます。

GnuCOBOL（C 言語トランスパイル）や Zeus（独自インタプリタ）に対し、`cobol-on-java` では **「Java 21 + ASM を用い、PL/I ソースコードから直接 JVM バイトコード（`.class`）を生成する（`pli-compiler`）」** アーキテクチャを採用しています。

このアプローチにより、以下の決定的メリットがもたらされます:
1. **中間の C/C++ コードやネイティブ共有ライブラリが一切不要**:
   コンパイル結果は標準的な Java クラスファイルであり、プラットフォーム非依存（Write Once, Run Anywhere）のポータビリティを維持。
2. **JIT コンパイラ（HotSpot）による実行時最適化**:
   Java 仮想マシンが実行時に頻出パスを検知し、インライン化やマシン語ネイティブコンパイルを動的に実施。
3. **COBOL / HLASM との同一アドレス空間内ゼロコピー呼出し**:
   同一 JVM プロセス内の通常メソッド呼出しとして動作するため、プロセス間通信（IPC）や JNI（Java Native Interface）のオーバーヘッドを完全に排除。

### 1.2 全体アーキテクチャ構成図

```text
+--------------------------------------------------------------------------+
|                        PL/I ソースコード (.pli)                          |
|  *PROCESS MARGINS(2,72);                                                 |
|  CALC: PROCEDURE(IN_AMT, OUT_TAX) OPTIONS(MAIN);                         |
|      DECLARE IN_AMT  FIXED DEC(9,2);                                     |
|      DECLARE OUT_TAX FIXED DEC(7,2);                                     |
|      OUT_TAX = IN_AMT * 0.10;                                            |
|  END CALC;                                                               |
+--------------------------------------------------------------------------+
                                     │
                                     ▼  [pli-compiler (Java 21 + ASM)]
+--------------------------------------------------------------------------+
| 1. コンパイル層: 構文解析 & バイトコード直接生成                         |
|   - プリプロセッサ: MARGINS(2,72), %INCLUDE, %DECLARE, %IF マクロ展開     |
|   - 構文解析器: Enterprise PL/I 構文木 (AST) の構築                      |
|   - 型システム & 構造体ペアリング算法 (ビット・バイト境界計算)            |
|   - JVM クラスファイル直接生成:                                          |
|     * 静的領域 (STATIC) -> クラス static フィールド / 初期化バイト配列    |
|     * 自動領域 (AUTOMATIC) -> メソッドスタック / フレームローカル変数    |
|     * 基于領域 (BASED) -> ByteArrayView ポインタオフセット操作           |
+--------------------------------------------------------------------------+
                                     │
                                     ▼  [.class 生成]
+--------------------------------------------------------------------------+
| 2. 実行時メモリ統合層: ByteArrayView (同一 JVM アドレス空間)              |
|   - 連続生バイト配列 (byte[]) をバッキングストアとするゼロコピービュー   |
|   - EBCDIC 文字列, COMP-3 (パック10進数), ビッグエンディアン 2進数       |
|   - ポインタ型 (POINTER) -> バッキング配列参照 + 相対オフセット (int)    |
+--------------------------------------------------------------------------+
                                     │
                                     ▼  [多言語相互呼出: CALL 規約]
+------------------------------------+-------------------------------------+
| COBOL 呼び出し元 / 呼び出し先       | HLASM (アセンブラ) 連携モジュール   |
| (CALL 'CALC' USING AMT, TAX)       | (MVSWAIT, COBDATFT 相当)            |
+------------------------------------+-------------------------------------+
```

## 2. データ型マッピングと `ByteArrayView`

PL/I のデータ型は、`cobol-runtime` が提供する高性能なメモリ操作機構 `ByteArrayView` 上に厳密に配置されます。

### 2.1 主要データ型の配置仕様

| PL/I データ型定義 | 物理バイトレイアウト | `ByteArrayView` 操作 | 変換・演算仕様 |
| :--- | :--- | :--- | :--- |
| **`CHARACTER(n)`** | EBCDIC 037 固定長バイト列 | `slice(offset, n)` | 常に EBCDIC 生バイトのままメモリに保持。 |
| **`CHAR(n) VARYING`** | 2バイト長（Big-Endian）+ データ | `readShort()`, `slice()` | 長さプレフィックス付き可変長文字列。 |
| **`FIXED DECIMAL(p, q)`** | パック10進数（Packed Decimal） | `getPackedDecimal()`, `setPackedDecimal()` | 末尾符号ニブル（`C`/`D`/`F`）を持つ z/OS 互換形式。丸め・桁あふれを厳密に計算。 |
| **`FIXED BINARY(15)`** | 2バイト 符号付き 2の補数 | `getShort()`, `setShort()` | ビッグエンディアン 16bit 整数。 |
| **`FIXED BINARY(31)`** | 4バイト 符号付き 2の補数 | `getInt()`, `setInt()` | ビッグエンディアン 32bit 整数。 |
| **`POINTER`** | 4バイト オフセット（内部表現） | `getInt()`, `ref()` | バッキング配列参照とオフセットのペア。 |
| **構造体 (`1 STRUC, ...`)**| ペアリング算法によるパディング | 構造体定義に基づくレイアウト | IBM Enterprise PL/I 規格の整列境界に従って正確にアライメントを挿入。 |

## 3. 同一 JVM 上での多言語相互呼出（COBOL ⇄ PL/I ⇄ HLASM）

### 3.1 ゼロコピー引数渡し（Reference Passing）
メインフレームの `CALL` 規約（標準リンケージ規約）では、引数のアドレス（ポインタ）のリストがレジスタ 1（R1）に設定されて渡されます。

`cobol-on-java` では、このリンケージ規約を Java のインターフェースとして表現しています:

```java
public interface ExecutableUnit {
    // 引数はすべてメモリ上の生バイト列へのビュー (ByteArrayView)
    int execute(CobolSession session, ByteArrayView[] arguments);
}
```

1. **COBOL から PL/I の呼び出し**:
   - COBOL: `CALL 'PLIPROG' USING BY REFERENCE WS-DATA, WS-TAX.`
   - 生成バイトコードは、`WS-DATA` と `WS-TAX` の `ByteArrayView` スライスを作成し、`PLIPROG.class` の `execute` メソッドを呼び出します。
2. **PL/I 側での参照**:
   - PL/I: `PLIPROG: PROCEDURE(P_DATA, P_TAX);`
   - 引数として受け取った `ByteArrayView` をそのまま手続き内のローカル変数バッファとしてバインド。
   - PL/I 内で `P_TAX` に値を代入すると、COBOL 側の `WS-TAX` の物理バイト列が即座に書き換わります（コピー＆書き戻しではないため、完全なリアルタイム共有が成立）。

## 4. 入出力および例外処理の実装

### 4.1 ストリーム入出力（`PUT SKIP LIST` / `GET EDIT`）
- `PUT SKIP LIST(...)`:
  引数を文字列化して標準出力または指定された DD ファイル（`SYSPRINT`）へ出力。PRINT 属性のファイルでは、IBM 仕様に基づく既定タブ位置（25, 49, 73, 97 桁目）への空白埋めを自動実行。
- `GET EDIT(...) (FORMAT)`:
  書式指定子（`A`, `F`, `X` 等）に従い、入力ストリームから固定桁数を切り出して変数へバインド。

### 4.2 例外ハンドリング（ON ユニット）の Java 実装
PL/I の `ON <condition>` 文は、Java のスレッドローカルな例外ハンドラスタックとして実装されています:
- 発生した例外（例: `ZERODIVIDE`, `CONVERSION`, `ENDFILE`）は、Java の `PliConditionException` としてスローされます。
- ランタイムのディスパッチャがスタックを巻き戻しながら、現在のアクティブなスコープに登録されている ON ユニット（ラムダ式 / コールバックメソッド）を特定して実行します。

## 5. 他処理系との比較

| 比較項目 | cobol-on-java (`pli-compiler`) | Zeus (`zeus-pli`) | GnuCOBOL (`extras/pl1c`) |
| :--- | :--- | :--- | :--- |
| **コンパイルターゲット**| **JVM バイトコード (.class) 直接生成** | ZIR 中間表現 (インタプリタ実行) | C 言語ソースコード (GCC ビルド) |
| **実行エンジン** | **HotSpot JIT コンパイラ (高速実行)** | Rust 製インタプリタ VM | ネイティブマシン語バイナリ |
| **多言語統合** | **同一 JVM 内ゼロコピー メソッド呼出し**| 実行単位メモリ統合 (`interlang::XRef`)| C 言語リンケージ (FFI) |
| **プラットフォーム性** | **Java が動く全環境 (Linux, Windows, K8s)**| ネイティブバイナリ (クロスコンパイル)| GCC / C ライブラリ依存 |
| **ポインタとメモリ** | `ByteArrayView` 上のオフセット安全管理 | リニアメモリ上の絶対番地 | ネイティブポインタ |
